## Идея

**Business AI (Sab0tage)** — AI-ассистент для начинающих предпринимателей в контексте ВТБ. Пользователь пишет «Хочу открыть кофейню», отвечает на вопросы про город, бюджет, формат, ограничения и финансирование. Ассистент через аналитические инструменты рекомендует **3–5 перспективных зон/помещений** с объяснением, показывает конкурентов, инфраструктуру и финансовые сценарии, затем предлагает подходящие продукты банка. По **отдельному согласию** формирует квалифицированную заявку.

**Две стороны пользы:** предпринимателю — сравнение и снижение неопределённости; ВТБ — раннее привлечение клиентов, персонализированные услуги и потенциальная экономика цифрового канала. Финансовый эффект для банка ещё **не доказан**; не утверждай рост капитализации от аналога Сбера.

## Инварианты (обязательные правила)

1. **LLM — оркестратор/объяснитель**, а не источник геофактов, трафика, аренды или финансовых расчётов. Все цифры приходят из типизированных сервисов.
2. Рекомендации локаций **объяснимы**, воспроизводимы и независимы от желания банка продать кредит.
3. Каждая метрика имеет **source/provenance**, дату, вид `origin` (`open_data`, `licensed`, `modelled`, `synthetic`, `user_input`, `bank_internal`) и ограничения. `synthetic` всегда явно показывается.
4. Если нет законных данных о свободных помещениях, рекомендуем **районы/зоны** или сравниваем введённые пользователем адреса, а не выдумываем объявления.
5. Настоящий кредитный скоринг **не делаем по переписке**. Только добровольная квалификация интереса; кредитный риск оценивают банковские системы при наличии оснований.
6. Реальная передача данных в ВТБ — только с отдельным согласием и после согласованной интеграции. Пока это `mock` и так помечено.
7. Не скрейпим закрытые сервисы вопреки условиям; коммерческие источники — только по лицензиям/договорам.
8. Цель — **весь продукт от MVP до банковского пилота и масштабирования**, а не только первый спринт.

## Первые технологии и архитектура

Модульный монолит: **React+TypeScript/MapLibre → FastAPI/Python → Postgres+PostGIS**. Модули: диалог/состояние профиля, LLM adapter, источники геоданных, ранжирование, финансирование, каталог банковских продуктов, consent/лиды. OSM/GHSL — open data; для missing traffic/spend/rent допускаются синтетические наборы с маркировкой. Для MVP LLM — локальная Qwen через Ollama, без платных облачных API и обучения; сменный адаптер и явный stub для тестов (ADR-0002). Compose для Windows/WSL2, pytest, lint/typecheck, GitHub CI, project `prek.toml`.

## Основной demo flow

«Хочу кофейню в Казани с бюджетом 2 млн» → уточнение → профиль → поиск зон/сравнение адресов → карта и причины → 3 финсценария + безубыточность → РКО/эквайринг и другие подходящие услуги → предпросмотр и **mock**-заявка по согласию.

Казань и кофейня — **примеры**, пока не утверждённые условия пилота.
