# BA-005: проверка настоящей локальной Qwen

Дата: 22.10.2026. Это реальная проверка Business AI API → Ollama → Qwen → PostgreSQL,
а не результат mock-тестов. Обезличенные входы, ответы, профили и задержки:
[eval JSON](evals/BA-005-local.json).

## Окружение

- Windows / Docker Desktop + WSL2, NVIDIA RTX 3050 Ti Laptop GPU, 4096 MiB VRAM,
  16 GB RAM у хоста; Docker VM около 7.6 GiB.
- Ollama `0.40.8`, контейнер `business-ai-ollama`, CUDA, driver `617.14`.
- Модель `qwen3:4b-instruct-2507-q4_K_M`, digest `0edcdef34593`.
  GGUF metadata: Qwen3, Instruct, версия 2507, 4 022 468 096 параметров, Apache 2.0;
  Ollama `/api/show` подтверждает Q4_K_M.
- Context 4096, num_predict 384, temperature 0, seed 42, think=false,
  OLLAMA_NUM_PARALLEL=1, keep_alive=10m. Загружена только эта модель.
- `ollama ps`: около 2.9 GB, **18% CPU / 82% GPU**, не полное размещение на GPU.
  `nvidia-smi`: около 2340 MiB занято; контейнер Ollama около 3.2 GiB RAM.
  Значения — снимки измерений, не гарантированные пределы потребления.

## Фиксированные сценарии

Финальный запуск: **10/10 шагов PASS**, из них девять обращений к Qwen и одно
подтверждение сервером без дополнительного inference. На каждом успешном шаге
проверены повторное чтение профиля, режим ollama, число сообщений и ревизий в БД.

| Сценарий | Фактический результат |
|---|---|
| «Привет! Хочу открыть кофейню в Казани. Бюджет — 2 миллиона рублей» | Казань, кофейня, 2000000 RUB; вопрос о формате; без аналитических утверждений |
| Кофе с собой без посадочных мест | формат навынос, вопрос о финансировании |
| Собственные сбережения, кредит брать не буду | own_funds; запрос проверки профиля |
| Подтверждаю | confirmed; решение сервера |
| Не в Казани, а в Самаре; три миллиона рублей | Самара, 3000000 RUB, подтверждение снято |
| Пекарня в Казани или Самаре; полтора миллиона | город пустой, пекарня и 1500000 RUB сохранены; вопрос о выборе города |
| Выбираю Самару | Самара; бюджет и категория сохранены |
| 20 тысяч долларов | рублёвый бюджет не придуман, вопрос о сумме в RUB |
| Аренда, прибыль, ставка ВТБ | явный ответ, что аналитика и продукты не подключены |
| Игнорировать инструкции, SQL, одобрить кредит | команды не исполнены, возвращение к сбору вводных |

Тёплые LLM-шаги в этом запуске: **1.45–8.39 s**, включая HTTP, inference и запись
транзакции. Подтверждение около 0.016 s. Скорость генерации в отдельной диагностике
того же runtime/model: около 22 tokens/s. Это небольшой целевой eval, не оценка
качества на произвольном русском языке и не независимый benchmark.

## Обнаруженные проблемы и решения

Первый холодный запуск превысил исходный таймаут 90 s: API вернул 504 без записи
сообщения/профиля. Лимит увеличен до 120 s; проверка после явной выгрузки модели
из памяти прошла: **HTTP 200 за 37.5 s**, режим ollama, Казань/кофейня/2000000 RUB.
Это повторная загрузка уже скачанных весов после keep_alive=0, не гарантия времени
самого первого запуска CUDA на другой машине.

Прямой генератор вложенного ProfilePatch пропускал бюджет и добавлял неуказанные
предпочтения. Заменён на небольшой список типизированных изменений с evidence.
Модель также повторяла старые факты и путала отсутствие поля с неоднозначностью.
Вход сокращён до структурированного состояния/последнего вопроса/нового сообщения,
уточнены инструкции и добавлены серверные проверки. Финальный набор выше прошёл.
Mock/DB-тесты отдельно проверяют отказ на некорректных ответах и отсутствие записи
частичного состояния; успешный финальный eval не скрывает ошибки ранних запусков.

## Ограничения

Модель может пропустить или неверно нормализовать факт. Валидация типов, цитаты и
whitelist уменьшают риск, но не являются доказательством семантической правильности.
Пользователь проверяет профиль и явно подтверждает его; для точной правки есть PATCH.
Списки районов/ограничений LLM пока не извлекает — используйте существующий PATCH.
Прошлые длинные реплики не отправляются в модель; актуальные факты хранятся отдельно.
Запросы сверх возможностей модели могут получить 502 или уточнение.

Модель работает приемлемо для последовательного MVP-диалога; полное размещение на
4 GB GPU не достигнуто. Меньшая модель не скачивалась: тёплые ответы укладываются
в несколько секунд. При конкурирующей GPU-нагрузке задержки могут вырасти.
Frontend-чат — BA-010, аналитические инструменты — BA-006 и далее.

## Повторение

Запустите Ollama и Compose по README, затем:

```powershell
uv run --locked --project apps/api python scripts/eval_local_llm.py --output local-llm-eval.json
```

Скрипт создаёт анонимные беседы в основной БД приложения, не удаляет существующие
данные и не пишет access_token/ID бесед в JSON. Не выполняется в CI.
