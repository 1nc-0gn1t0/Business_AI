# Источники данных BA-014

Модуль `app.data` работает внутри существующего FastAPI-монолита. Пользовательские
запросы читают локальные PostgreSQL/PostGIS; HTTP-запросов к внешним поставщикам нет.
Ни LLM, ни параметры клиента не могут назначать origin, лицензию или исходные значения.

## Адаптеры и контракты

`DataProvider` — Protocol с `datasets(session)` и `read(session, IndicatorQuery)`.
Реестр `providers()` возвращает взаимозаменяемые реализации одного контракта:

| Адаптер | Готовность | Данные |
|---|---|---|
| OSMProvider | Работает | Исторические и активные snapshots BA-006, bbox-count POI/кафе в PostGIS |
| SyntheticProvider | Работает после явного импорта/включения | Авторский сценарий кофейни; не рыночные наблюдения |
| GHSLProvider | Контракт, не подключён | Проверенного локального набора нет; возвращает unavailable |
| LicensedProvider | Контракт, не подключён | Нет договора/источника/внешних вызовов |

OSM fetch-протокол `app.geo.provider.OSMProvider` BA-006 остаётся отдельным
операторским интерфейсом ingestion; новый `app.data.providers.OSMProvider`
адаптирует уже проверенное хранилище для чтения показателей. Повторного импорта OSM нет.
GHSL и licensed не создают фиктивные данные, названия партнёров или обещания интеграции.

Значения — существующий `MetricWithProvenance` BA-003 и `DataOrigin`.
`Indicator` оборачивает его в nullable `measurement`: `missing`/`outside_coverage`
не имеют числа, `available`/`stale` имеют значение. Ноль считается наблюдаемым
нулём *картированных features*, а не отсутствием реального бизнеса.
Идентификатор/название/числовой тип/единица явные. Метаданные `ProviderDataset`
наследуются каждой метрикой: bbox EPSG:4326, источник, лицензия, атрибуция,
даты, версия, active/history, срок пересмотра, качество и ограничения.
`IndicatorResult` запрещает смешение origin/source/version и синтетику в real mode.
Для новых денежных расчётов сохраняется Decimal-контракт BA-009; float здесь —
совместимый числовой DTO BA-003, не финансовая арифметика.

OSM origin=open_data, confidence=low. `observed_at=osm_base` — время среза/редактирования,
не измерение на местности. `generated_at` у агрегата — время ответа, поэтому
воспроизводимы значения и fingerprint, но не служебная дата вычисления.
Count по точкам/центрам объектов внутри bbox, без экстраполяции; покрытие bbox не
гарантирует полноту картирования. Трафик/аренда/спрос из OSM не вычисляются.

## Политика выбора

По умолчанию `mode=real`, `DATA_DEMO_ENABLED=false`. Для синтетики нужны **оба**
условия: серверное `DATA_DEMO_ENABLED=true` и явное `mode=demo` в каждом запросе.
Отдельный POST selection проверяет выбор, но не создаёт глобальное состояние:
никакой режим одного гостя не меняет другой сеанс. Выбор UI локален компоненту,
после reload возвращается real. Настройка относится к новым провайдерским данным;
существующие явно помеченные сценарные вводные BA-009 остаются независимыми.

Нет fallback между источниками, автоматического объединения, пересчёта
рейтинга по синтетическому потоку, переноса аренды в финансы или банковского matching.
BA-008 и BA-013 сохраняют свои API/версии/источники. Будущее включение новых
признаков потребует отдельной явной версии алгоритма и правила смешения.

## Набор и импорт

`data/synthetic/coffee-kazan-v1.json`: фиксированные авторские значения
`fixed-authored-scenario-v1`, без случайности, внешних измерений или калибровки:
1800 условных людей/день, 90000 условных RUB/месяц, 90 сценарных покупок/день.
Эти числа независимы: покупки не выводятся из потока. Bbox — условная привязка
демонстрационного сценария к части Казани, не рынок и не конкретное помещение.
Значения действуют только для полного объявленного bbox; запрос подмножества
возвращает outside_coverage, не масштабирует их пропорционально площади.
Origin=synthetic, observed_at=null, confidence=not_applicable у каждого значения.
Generated_at фиксирован, лицензия авторских демо-данных CC0-1.0.

В PowerShell из корня репозитория:

```powershell
$env:DATA_DEMO_ENABLED = 'true'
docker compose up --build --detach --wait
# Либо DATA_DEMO_ENABLED=true в локальном .env; секреты/веса здесь не нужны.
docker compose cp data/synthetic/coffee-kazan-v1.json api:/tmp/coffee-kazan-v1.json
docker compose exec -T api python -m app.data.importer /tmp/coffee-kazan-v1.json
```

Нормальный вывод CLI — SHA256 принятого набора, после commit транзакции.
Импорт <=256 KiB: Pydantic проверяет единицы/конечные неотрицательные числа,
origin, даты, источник, дубли metrics, ограничения, revision и схему.
Версия — SHA256 канонической сериализации валидированной модели, включая
revision/метод/дату/географию/лицензию/значения. Изменённое содержимое под прежней
revision запрещено. Для обновления задайте новую revision и более поздний generated_at.
Не переписывайте опубликованный файл; создавайте новый файл. В БД 0007 хранит
JSONB исходного контракта, SHA/revision/imported_at/active, старые версии сохраняются.
Advisory transaction lock + unique constraints + atomic active swap предотвращают
дубли/гонки. Replay идемпотентен и не реактивирует старую версию. Ошибка импорта
не меняет активный набор. При чтении проверяются схема/SHA/identity; повреждение →503.
Пользовательского API записи/импорта нет. Для большого числа snapshots потребуется
пагинация/retention, но автоматическое удаление не реализовано.

Полное отключение демонстрационных данных (без удаления истории/volumes):

```powershell
$env:DATA_DEMO_ENABLED = 'false'
docker compose up --detach --wait api
```

## API

- GET `/api/v1/data-providers/sources`: готовность, происхождение, ограничения адаптеров.
- GET `/api/v1/data-providers/policy`: default real и серверный флаг.
- POST `/api/v1/data-providers/selection` `{ "mode": "demo" }`: явная проверка режима.
- GET `/api/v1/data-providers/{provider}/datasets`: метаданные и история версий;
  отключённая синтетика и неподключённые адаптеры возвращают пустой список.
- POST `/api/v1/data-providers/indicators`:

```json
{
  "provider": "osm",
  "dataset": "kazan-centre",
  "data_version": "<SHA256 из datasets>",
  "mode": "real",
  "metrics": ["mapped_poi_count", "mapped_cafe_count", "rent_monthly_rub"]
}
```

Дополнительный `bbox` разрешён в границах покрытия OSM. Без bbox — полный набор.
Поддерживаются пять ID из `schemas.METRICS`, неизвестные/повторяющиеся →422.
Ответ включает полный provenance, bbox, dataset, selection, метод и fingerprint.
Fingerprint включает версию адаптера, provider/dataset/version/mode/bbox/список метрик;
его нельзя сравнивать как бизнес-score. Историческая версия читается явно, не
подменяется текущей. Источник/версия меняются — UI немедленно убирает результат;
для новых значений нужен запрос. Обновление списка также убирает результат.
Текущий экран — snapshot, не real-time подписка на обновления каталога.

Ошибки:403 demo_data_disabled;409 provider_version_not_found;
503 provider_not_integrated/provider_dataset_invalid/database_unavailable.
Неизвестный provider/невалидный запрос →422. Все SQL-параметры связаны.
Устаревание — предупреждение, не замена: OSM >30 дней, synthetic >365 дней
(срок пересмотра демо, не срок достоверности рынка). Историчность отдельно active=false.

## Интерфейс и проверки

На карте/сравнении раскрывается «Источники и происхождение показателей».
Режим → источник → версия → явная загрузка. Показываются пропуски, origin,
даты, лицензия, атрибуция, ограничения и полный JSON. Синтетика помечена в заголовке
и каждой строке. Таблица прокручивается внутри панели на мобильном экране.
Карта и предыдущие результаты не становятся синтетическими при переключении.

Unit/API/PostGIS-тесты проверяют схему/provenance, реальный SQL count,
воспроизводимость, stale/missing/outside, отсутствие fallback, disable policy,
исторические версии/конфликт/повреждение, неизменность BA-008/013.
Frontend проверяет явный режим, сброс результатов и ошибки. CI использует локальные
фикстуры и mock LLM, без GPU/внешнего банка/платных источников.
Настоящая проверка: включённый флаг, импорт OSM/графа/демо и работающая Qwen,
затем `BA010_REAL=1 npm --prefix apps/web run test:e2e` (PowerShell: env переменная).
Реальные HTTP-примеры — `docs/examples/BA-014-provider-indicators.json`;
скриншоты/результаты — HANDOFF. Это разные проверки от mock-тестов.
