# ADR-0001: состояние беседы и подтверждение профиля

Дата: 20.10.2026. Статус: принято в реализации BA-004, на review в PR.
Основание: PROJECT_PLAN, F-01/F-02, разделы 5, 9, 11 и задача BA-004.

## Решение

Сохраняется модульный монолит FastAPI/PostgreSQL. Маршруты вызывают сервис бесед;
чистые функции извлечения и переходов используют DTO BA-003. Состояние, сообщения
и история снимков профиля сохраняются в БД, переживая перезапуск процесса.

Состояния: collecting → awaiting_confirmation → confirmed. Для первого сценария
обязательны категория, город, положительный общий бюджет в рублях, формат и источник
финансирования. Районы/ограничения доступны через PATCH и не блокируют подтверждение.
Подтверждение означает проверку вводных пользователем, а не запуск аналитики,
согласие на передачу лида или кредитное решение.

Изменение значений снимает подтверждение; пустая правка сохраняет его. PATCH
различает отсутствие ключа и null, объединяет вложенные предпочтения. Подтверждение —
отдельное действие или строго распознанная фраза целиком, только для полного профиля.

До BA-005 извлечение работает по ограниченным локальным правилам. Ответ содержит
extraction_mode=rules. Для произвольных названий предусмотрены явные метки и PATCH.
Никакого LLM-провайдера, tool calling, геофактов или финансовых расчётов здесь нет.

Гостевой доступ к одной беседе защищён случайным 256-битным токеном в заголовке
X-Conversation-Token. Токен возвращается один раз, в БД — только SHA-256.
Неизвестный UUID и чужой токен возвращают одинаковый 404; отсутствие токена — 401.
Токен не входит в URL, историю, снимки и сообщения об ошибках. Это не аккаунтная система.

Запись требует expected_version. SELECT FOR UPDATE и проверка версии предотвращают
потерю параллельных изменений; устаревший клиент получает 409. Профиль, сообщения,
состояние и снимок сохраняются одной транзакцией. Function-scope dependency FastAPI
завершает commit до отправки успешного ответа. История/сообщения имеют пагинацию.

Уточнение H-03 (26.10.2026): для POST messages вместо request-scoped Session используется
factory. Read snapshot и final write имеют разные Session/короткие транзакции с commit
до возврата DTO; во время очереди/inference соединение возвращено в pool. Patch/confirm
и остальные операции сохраняют function-scope dependency. См. [ADR-0002](ADR-0002-local-llm.md).

Миграция 0002 добавляет conversations/messages/profile_revisions и FK профиля.
Старые профили сохраняются со снимком legacy_import, без выдачи гостевого доступа
(хеш-заглушка). Автоматического восстановления доступа к ним нет. Downgrade удаляет
новые таблицы/enum/FK, сохраняя сами business_profiles и PostGIS.

## Альтернативы и последствия

Память процесса не обеспечила бы сохранность истории и несколько экземпляров API.
Полная LLM-интеграция относится к BA-005. Запись без контроля версии теряла бы правки.

Клиент сохраняет токен и версию; после 409 перечитывает профиль и осознанно повторяет
исправление. Потерянный гостевой токен не восстанавливается публичным API. Аккаунты,
сроки хранения и полноценная защита публичного сервиса — отдельные задачи пилота.
