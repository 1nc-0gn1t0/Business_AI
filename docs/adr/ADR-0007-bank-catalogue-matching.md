# ADR-0007: проверяемый каталог и трёхзначный банковский подбор

Дата: 23.10.2026, BA-011. Сохраняется модульный монолит.

Отдельный `app/bank` содержит типизированный JSON-каталог Product,
EligibilityRule, EvidenceSource и чистый детерминированный matcher.
Правила описывают **релевантность потребности**, не полную банковскую eligibility.
Нет eval, произвольных выражений, весов, банковской маржи, кредитного или OSM-score.

Каталог читается локально на запрос, версионируется строкой и SHA-256 канонического
JSON. Обновление данных/правил не требует переписывать алгоритм. Сломанный каталог
даёт 503 без подстановки других предложений. Просроченные/будущие даты, снятые или
недоступные записи блокируются. Источник и продукт проверяются отдельно.

Прямая проверка официальных страниц ВТБ в рабочей среде не прошла TLS/HTTP;
доступен поисковый индекс официальных страниц. Поэтому начальные карточки
`mode=demonstration`, `status=unconfirmed`, источники `cached_only`,
`last_verified_at=null`. Они никогда не попадают в recommended_ids.
Для перехода к public_reference нужны ручная проверка назначения/условий,
дата и digest источника; наличие такого аттестата не является решением банка.

Подбор защищён существующим гостевым токеном беседы. Сервер читает актуальный
BusinessProfile, проверяет expected_version и подтверждение; не доверяет присланной
клиентом отметке confirmed. Дополнительные добровольные BankingNeeds передаются
отдельным DTO и снимком результата, без изменения BA-004 и без миграций.
Они не сохраняются в историю и не заполняются догадками из формата/категории.

Все правила продукта — AND с matched/unknown/not_matched. Явное несовпадение
исключает позицию; неизвестное требует уточнения. Financing — только справочный
интерес, не оценка клиента. Банк ничего не получает; LLM и платные API не участвуют.
Сквозной UI использует тот же API; BA-012 здесь не реализуется.
