# ADR-0009: ограниченный пешеходный граф OSM

Принято для BA-013, 24.10.2026. Продолжает ADR-0003/0004/0005.

Отдельный дорожный snapshot и walk_graphs/walk_edges в PostGIS (0006) сохраняют
POI BA-006. Топология только по node IDs: пересечения мостов не соединяются
геометрически. Направления/access/barriers применяются сервером.
Стоимость geography в метрах; привязка в локальной UTM; GeoJSON WGS84.

Bounded Dijkstra heapq на индексированном локальном срезе достаточен для первой
области на 16 GB RAM. Новые pgRouting/NetworkX/routing server не требуются.
Компоненты предварительно вычислены. Кеш/исторические версии на диске/в PostgreSQL,
без большого процесса в памяти рядом с Ollama. Нет платного API или новой модели.

Возвращаются достижимые интервалы рёбер, не buffer/convex hull, который мог бы
закрасить непроходимые кварталы. Соединители ограничены и явно модельные;
ближайшее ребро выбирается независимо от достижимости. Неосновные компоненты
показываются, но не ранжируются. Это фильтр качества, не доказательство изоляции.

Opt-in walking-rankings возвращает baseline/network параллельно. Веса/min-max
BA-008 сохранены, версии метода/политики разные. Нет скрытой подмены дистанций,
плотности по фиктивной площади и связи с выручкой/банком. Прежний API сохранён.
UI явно предлагает новую группу кандидатов во внутреннем окне графа.

Компромиссы: conservative foot policy; conditional access и foot restriction
исключаются вместо temporal/turn-state engine. Неполные OSM/входы, снимки разных
дат, соединители, отсутствие wheelchair/3D/indoor routing объясняются в API/UI.
Обновление атомарное, старые версии не удаляются, лимиты ограничивают ресурсы.
Контракты/источники/измерения: [WALKING_CATCHMENT.md](../WALKING_CATCHMENT.md).
