# ADR-0003: ограниченные OSM snapshots и PostGIS-запросы

Дата: 22.10.2026. Задача BA-006. Архитектура модульного монолита сохранена;
LLM-модуль BA-005 не изменяется.

## Решение

Для первого доступного city extract используется OpenStreetMap через публичный
Overpass API. Выборка ограничена явно заданным WGS84 bbox: amenity, shop,
highway=bus_stop, административные relation уровней 8/9/10 с полной геометрией.
Это часть города, а не утверждение полного покрытия муниципальной территории.
Для MVP на 16 GB RAM не загружаются Россия целиком, дорожный граф или все здания.
PBF/Geofabrik и маршрутизация потребуют отдельных адаптеров; BA-013 здесь не реализуется.

`OSMProvider` отделяет загрузку от импорта. CLI fetch сохраняет Overpass JSON и
manifest: точный запрос, bbox, URL, дату upstream osm_base, дату загрузки, SHA256,
ODbL и атрибуцию. Нормализация poi_minimal_v1 удаляет user/uid/changeset и
ненужные контактные/прочие теги, сохраняя геометрию, OSM ID/version/timestamp и
используемые POI-теги. В manifest есть хеш исходного ответа и хеш сохранённого
JSON. `data_version` — второй хеш; это идентификатор данных, не цифровая подпись.
Старые ненормализованные локальные snapshots читаются как normalization=none.

CLI import не делает сетевых запросов: проверяет manifest/хеш/запрос/даты и
воспроизводит сохранённый snapshot. Новая загрузка — отдельный файл; существующий
кеш не перезаписывается. Таймаут/HTTP error/remark Overpass не становятся пустым
успешным набором. Автоматических повторов к публичному сервису нет.

## Хранение и обновление

Миграция 0004_osm_geo добавляет geo_datasets, geo_pois, geo_districts. Данные OSM
хранятся отдельно от location_metrics и коммерческих предположений. Отдельные
версии набора неизменны; уникален активный slug. Advisory transaction lock на slug
сериализует импорт. Повторный хеш идемпотентен. Более старый osm_base отклоняется;
изменение bbox/запроса требует нового slug. Пустая POI-выборка по умолчанию запрещена.

POI/полигоны/диагностика загружаются и активная версия переключается в одной
транзакции. Неудача сохраняет прежнюю активную версию; старые версии не удаляются.
Удалённый из нового snapshot объект исчезает из активного слоя, оставаясь в истории.
Внешний API доступен только для чтения; загрузка/импорт — операторские команды.

POI идентифицируется парой osm_type/osm_id, а не названием. Node сохраняет свою
точку. Way/relation использует полученный от OSM bbox center с явной маркировкой
osm_bbox_center. Это не адрес входа и не геометрия здания. Центры вне области
не импортируются. Неизвестное имя остаётся null; даты не подменяются временем импорта.

Административные границы собираются ST_BuildArea из полных member ways; все линии
должны замкнуться, итог — валидный непустой MultiPolygon. Незамкнутые/неполные,
невалидные и вложенные relation пропускаются с диагностикой, не восстанавливаются
догадками. Overpass bbox выбирает relation по member nodes: наличие охватывающего
района для каждого viewport не гарантируется. Нужна более широкая выборка, если
конкретной границы нет. Полигон района может выходить за bbox покрытия POI.

## Запросы и производительность

GeoJSON API использует bbox, точную OSM-категорию и/или ST_DWithin по geography
(метры), ST_Distance для расстояния и ST_Covers для административного полигона.
Расстояния прямые, не пешеходные маршруты. Индексы: GiST geometry, GiST выражения
geom::geography, GIN categories, PK по версии набора/OSM identity. После импорта
обновляется статистика ANALYZE. Новых Python-зависимостей нет: геометрия обрабатывается
в PostGIS, небольшой SQLAlchemy Geometry type поддерживает Alembic reflection.

Лимиты: bbox до 0.1 квадратного градуса, snapshot до 64 MiB/100000 элементов,
батчи 500 POI, radius до 10 km, выдача до 500 POI, offset до 10000. Страницы после
первой требуют data_version; при обновлении слоя — 409, чтобы не смешивать версии.
SQL параметризован, HTTP API не обращается к Overpass. Реальные измерения и
ограничения — GEO_DATA.md. Для большого покрытия понадобятся PBF, retention и тайлы.

Пустой результат означает отсутствие подходящих *нанесённых объектов в загруженном
покрытии*, а не отсутствие бизнеса/конкурентов. OSM timestamp — последнее редактирование,
не дата физической проверки. Нет трафика, спроса, аренды, выручки, кредитных условий
или рекомендаций BA-007/BA-008. Атрибуция и ограничения передаются с каждым слоем.
