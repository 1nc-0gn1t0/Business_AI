# BA-008: сравнительная оценка географического окружения

`POST /api/v1/geo/{slug}/rankings` — read-only FastAPI/PostGIS-инструмент.
BA-007 создаёт кандидатов; новый модуль считает наблюдаемые признаки и рейтинг.
LLM, Overpass и внешние коммерческие источники не вызываются. Миграций и новых
зависимостей нет. Решение: [ADR-0005](adr/ADR-0005-zone-ranking.md).

## API

```json
{
  "candidates": {
    "profile": {
      "conversation_id": "00000000-0000-0000-0000-000000000008",
      "city": "Казань",
      "category": "кофейня",
      "budget": "2000000",
      "confirmation_state": "confirmed"
    },
    "search_bbox": {"west": 49.065, "south": 55.71, "east": 49.235, "north": 55.84},
    "cell_size_m": 500,
    "min_separation_m": 1000,
    "limit": 5
  },
  "scoring": {
    "version": "osm-relative-v1",
    "radius_m": 500,
    "weights": {"transit": 1, "infrastructure": 1, "complementary": 1, "competitors": 0},
    "competitor_mode": "neutral"
  }
}
```

`candidates` — существующий CandidateRequest, включая optional `data_version`,
районы/исключения и proximity constraints. Сервер повторно строит кандидатов,
не принимает произвольные геометрии или баллы клиента. Неизменённый запрос
BA-007 с той же версией данных даёт те же геометрии/ID независимо от scoring.

Вход — **переданный снимок** BusinessProfile, как в BA-007. Нужен
`confirmation_state=confirmed`, иначе 200 `needs_confirmation`, без оценок.
Этот флаг — утверждение вызывающего клиента, не авторизация доступа к беседе:
endpoint не читает/не подтверждает сохранённый профиль по UUID. Оркестратор
должен получать актуальный подтверждённый профиль через защищённый API диалога.
Правила подтверждения/конкурентного редактирования BA-004 не изменяются.
Прямой инструмент годится для операторской проверки переданного сценария;
сохранённый AnalysisRun и автоматический вызов из чата здесь не создаются.

Бизнес-категория выбирает списки конкурентов/окружения; подтверждённые районы,
ограничения и город действуют через BA-007. Бюджет, funding и format сохраняются,
но **не влияют на число баллов** без данных о стоимости/помещениях. Неизвестные
hard constraints блокируют генерацию, как прежде. Не следует переводить площадь
или предельную аренду в фиктивное условие близости к POI.

Ответ `RankingCollection` содержит:

- `candidates`: неизменённый типизированный CandidateCollection BA-007 с GeoJSON,
  source/date/license, снимками профиля/запроса и версиями геометрии;
- `evaluations`: оценки, упорядоченные по score ↓, затем candidate_id ↑; строки
  без score идут последними по ID. Для карты соединяйте по `candidate_id`;
- для каждой оценки: `score` 0…100 или null, ordinal `rank` или null, исходные
  `raw` метрики, `components` с min/max, нормализацией, весом и вкладом,
  четыре структурированных объяснения, `missing_data`, provenance и версии;
- `comparison_ids`: только полностью покрытая сравнимая группа;
- полный `policy.config`, списки категорий, rationale, version/fingerprint,
  `algorithm_version`, общий `request_fingerprint`, ограничения и missing_data.

200: `ok`, `partial`, `insufficient_data`, `no_candidates`, `needs_confirmation`.
`ok` означает расчёт в рамках явно ограниченного OSM-набора, не полноту данных
о реальном городе. Неполнота/ошибки BA-007 отражаются в статусе и reasons.
404/409 смены snapshot, 422 неверных параметров/версий/ресурсных пределов,
санитизированный 503 БД наследуются без изменения существующих endpoints.

## Исходные признаки

Круг наблюдения — от представительной точки зоны, радиус 50…2000 m, default 500 m.
500 m — конфигурируемый размер локального сравнения, **не время/зона пешей доступности**.
`ST_DWithin(geography)` и `ST_Distance(geography)` используют метры на эллипсоиде;
дорожного графа, барьеров и расстояний от каждого места внутри зоны нет.

| Признак | Исходный показатель | Полярность в рейтинге |
|---|---|---|
| transit | 1 − nearest_bus_stop_m / radius; 0, если остановка в выгрузке не найдена | больше наблюдаемая близость → выше |
| infrastructure | число различных категорий инфраструктуры среди известных POI | больше категорий → выше |
| complementary | число известных POI из отраслевого списка окружения | больше объектов → выше |
| competitors | число потенциально конкурирующих OSM features | default нейтрально; явная гипотеза cluster ↑ или separation ↓ |

Дополнительно выдаются общее число известных POI, число остановок, ближайший
конкурент, число инфраструктурных объектов, их категории, counts всех категорий,
конкурирующие features/км² круга. Это не плотность реальных уникальных компаний.
Неизвестное расстояние — null, а не 0/бесконечность. За границей покрытия counts
и features/км² — нижние границы наблюдаемого, к нормализации не допускаются.

Для кофейни конкуренты — `amenity:cafe`; окружение — university, college, school,
shop:bakery/supermarket/convenience. Это гипотеза о релевантном соседстве,
не измерение посетителей, спроса или доли рынка. Широкий тег cafe может означать
не кофейню; возможны ложные совпадения и пропуски. Для пекарни, ресторана,
салона и продуктового магазина применяются разные списки `BUSINESS_CONTEXT`.

Инфраструктура: amenity bank, atm, post_office, pharmacy, clinic, hospital,
parking, bicycle_parking. Число категорий выбрано, чтобы множество одинаковых
парковочных объектов не заменяло разнообразие окружения. Группы категорий
не пересекаются; OSM node/way одной организации всё равно могут дублироваться.
Транспорт ограничен `highway:bus_stop`: прочие остановочные теги/метро в
выгрузке BA-006 неполны и не выдаются за отсутствующие транспортные линии.

## Покрытие, пропуски и нормализация

1. Читать один snapshot. После BA-007 повторно проверить data_version и считать
   все метрики по dataset ID; конкурентное обновление до этой проверки даёт 409,
   после — прежние immutable строки остаются доступны. Слои не смешиваются.
2. Считать расстояние от точки до границы фактического bbox. Граница сначала
   сегментируется в geometry EPSG:4326 шагом ≤0.001°, затем измеряется geography,
   чтобы длинные линии постоянной широты не превратились в другой геодезический
   контур. Требуется запас ≥radius+1 m. Запас 1 m — консервативный численный guard.
3. Исключить зоны с неполным кругом из сравнения. Сохранить их исходные наблюдения
   с предупреждением и null score/rank. Радиус автоматически не уменьшается;
   counts не масштабируются по доле покрытия. Граница выбранного района или
   search_bbox не обрезает окружение: наблюдение ограничено **набором**, а не
   территорией поиска бизнеса, иначе районы получили бы разные условия.
4. Нужно минимум две полностью покрытые зоны. Для каждого активного критерия
   применить min-max в этой группе: `n=(x-min)/(max-min)`. Для separation — `1-n`.
   Одинаковые положительные значения дают нейтральные 0.5.
5. Все значения критерия равны нулю → нет наблюдаемого сигнала: normalized=null,
   status=unavailable. Это консервативная политика: нельзя отличить реальное
   отсутствие объектов от отсутствия картирования. Если вес положительный,
   **вся группа получает insufficient_data**, а не скрыто перераспределённые веса.
   Включая separation: отсутствие конкурентов не превращается в 100 баллов.
   Для отдельной нулевой зоны при наличии наблюдений в других её 0 означает
   только меньше картированного контекста; ограничения OSM сохраняются.
6. Нормировать заданные веса один раз: `w_i / sum(w)`. `score=100×Σ(w_i×n_i)`.
   Вклад каждого критерия возвращается. Disabled → вклад 0, отсутствующий
   активный сигнал → null, итоговый score не выдаётся. Баллы округляются до
   6 десятичных до сортировки; равенства разрешаются ID, без заявления превосходства.

По умолчанию три разных наблюдаемых измерения имеют равные веса. Нет проверенной
статистики, оправдывающей предпочтение транспорта разнообразию услуг или окружению.
Это прозрачная начальная экспертная гипотеза, а не эмпирически найденный оптимум.
Конкурентам присвоен вес 0: высокая концентрация может означать и кластер, и
насыщение. Чтобы включить их, клиент явно выбирает cluster/separation и weight>0;
режим neutral с положительным весом отклоняется. Веса 0…100, сумма >0.
Иные веса — явная настройка клиента, а не автоматически подтверждённая гипотеза.

`osm-cohort-minmax-v1`, `osm-business-context-v1`, `osm-relative-v1` + SHA256
эффективной политики фиксируют формулы, списки и точные настройки. Общий hash
добавляет fingerprint BA-007 и GIS runtime; технические UUID не меняют баллы.
Повтор с теми же входами/данными/runtime воспроизводит raw, normalized, score и
порядок. `generated_at`, age_days/stale естественно меняются со временем.
Нельзя сравнивать баллы разных групп, радиусов и конфигураций.

## Реальный запуск: Казань, кофейня, бюджет 2 млн

```powershell
docker compose up --build --detach --wait
uv run --locked --project apps/api python scripts/eval_zone_ranking.py --output local-ranking-eval.json
uv run --locked --project apps/api python scripts/eval_zone_ranking.py --api http://127.0.0.1:5173 --output local-ranking-proxy-eval.json
```

Read-only скрипт не подтверждает сохранённую беседу: использует явно переданный
сценарный снимок. Требуется прежний `kazan-centre` и его pinned версия из BA-007.
Архив запроса, GeoJSON, raw/components, версий и проверок:
[BA-008-kazan-coffee.json](examples/BA-008-kazan-coffee.json).
Источник OSM/Overpass, osm_base `2026-10-22T20:27:36Z`, ODbL-1.0,
© OpenStreetMap contributors, 23852 POI; версия
`44157bdc66965a6239c3470d459668cf362a0e355f76893febf4556f838a8447`.

У четырёх из пяти **исходных** зон BA-007 круг 500 m обрезан bbox. Пять прежних
ID сохранены, но рейтинг withheld: одна покрытая зона не образует сравнение.
Для отдельного проверяемого сравнения явно задан внутренний search_bbox
49.065,55.71,49.235,55.84. BA-007 создала пять новых зон с полностью покрытыми
кругами; радиус остался 500 m. Не следует смешивать эту группу с исходной.

У #1 — 8 инфраструктурных категорий и 34 объекта окружения; ближайшая известная
остановка в 253.8 m. #2 ближе к остановке (66.8 m), но имеет 4 инфраструктурные
категории и 1 объект отраслевого окружения. У #3 — 6 категорий/13 объектов,
но bus_stop в круге выгрузки не найден; это не утверждение отсутствия транспорта.

нормализованный показатель не означает нулевую инфраструктуру или нулевой риск.
Competitors показаны без вклада в default score; явная смена весов на transit-only
меняет порядок и hash и отдельно сохранена в отчёте.

## Границы качества

Это сравнительная привлекательность по **картированным географическим признакам**,
а не прогноз спроса/прибыли или рекомендация аренды конкретного объекта.
Неполнота картирования может влиять на рейтинг даже при полном геометрическом
покрытии. OSM timestamp означает срез редактирования, не осмотр действующей точки;
stale=true после 30 дней даёт предупреждение, не скрытую поправку к score.
Нет жилого населения, офисной занятости, проходимости, дорожных барьеров,
платёжеспособности, аренды, площади, правового статуса, выручки и условий ВТБ.
Бюджет 2 млн не проверен на достаточность; missing_data перечисляет пробелы.

Формулы/порядок проверены автоматически и независимым SQL; экспертной полевой
проверки привлекательности и статистики фактических результатов бизнеса нет.
Рейтинг условен относительно выбранных пяти ячеек, не глобальный поиск лучшего
места Казани. BA-009 (финансовая модель) не реализуется в этой задаче.
