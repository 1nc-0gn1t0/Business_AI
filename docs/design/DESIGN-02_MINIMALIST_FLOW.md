# DESIGN-02 · минималистичный маршрут Business AI

28.10.2026. База: PR27 merged, main `357bbd5ec05a704af2cd82c1d09325647acefc87`.
Ветка `codex/DESIGN-02-minimalist-flow`. Итоговый SHA/PR/CI — в сообщении сдачи.

## Концепция

Один экран, одна задача, одно основное действие. DESIGN-01 с постоянной навигацией,
overview и аналитическими панелями заменён последовательным маршрутом. Начальная
страница содержит Business AI, один вопрос, ввод идеи и кнопку. Ненавязчивый footer
прямо указывает: независимый хакатонный прототип, не официальный сервис ВТБ.

Официальный [референс ВТБ](https://втб.рф/personal/kredit/) действительно просмотрен
в Chromium. Текстовая web-загрузка не сработала, браузерная страница была доступна.
Использованы общие визуальные принципы: белый фон, крупные тёмно-синие заголовки,
насыщенная синяя округлая кнопка, спокойные серые поверхности, свободное пространство.
Код, логотипы, банковские изображения и фирменные шрифты не копировались. Локальный
Golos Text/OFL остался прежним. Тёмная тема и animation frameworks не добавлены.

## Состояния и переходы

| Экран | Основное действие | Условие перехода и серверный источник |
|---|---|---|
| IDEA | Отправить идею | Перед первой отправкой отдельный диалог согласия с текстом API и выключенным checkbox |
| CHAT | Ответить на один вопрос | POST messages с expected_version; следующий вопрос определяется missing_fields |
| REVIEW | Продолжить | Серверный POST profile/confirm; только подтверждённый профиль открывает карту |
| LOCATION | Продолжить к расчётам | Есть ranking API и выбранный ID действительно входит в его candidates |
| FINANCE | Продолжить | Есть актуальный FinanceResult; изменение допущений немедленно блокирует переход |
| BANKING | К результату / продолжить без подбора | Подбор доброволен; для итогов нужна актуальная финансовая модель |
| SUMMARY | Скачать PDF | POST отчёта при необходимости, GET актуальности, GET файла; JSON использует тот же снимок |

`flow.ts` проверяет готовность; `App.tsx` управляет переходами. Это не счётчик шагов.
Кнопка назад доступна на каждом этапе. Основные аналитические модули остаются
mounted/hidden, поэтому возвращение сохраняет вводные в текущей вкладке. При
изменении профиля сбрасываются ranking, zone, finance, bank, walking, providers.
Финансовый компонент также пересоздаётся при изменении зоны или fingerprint рейтинга.

При reload запрашиваются реальный профиль, история и согласия с токеном в заголовке.
Подтверждённый профиль открывает локации с явным требованием повторить анализ;
завершённый черновик — review, неполный — чат. Не сохраняется фиктивный флаг
«всё рассчитано». Недоступная БД не вызывает неявного создания новой гостевой сессии:
есть повтор загрузки; 401/404 требуют нового проекта. Новый проект не удаляет прежние данные.

## Чат и подтверждение

Умеренная ширина, различимые сообщения, scroll внутри истории и composer внизу.
Неотправленный текст остаётся после ошибок и переходов назад; очистка только после
успешной операции. Индикатор ожидания настоящий. Stub явно подписан «не Qwen».

Проверка существующей интеграции показала: Qwen извлекает структурированный patch,
а клиентский текст вопроса уже формируется детерминированно `reply_for` на сервере.
Поэтому сокращены только QUESTIONS и этот formatter: один отсутствующий параметр,
без повторения всего профиля. Не менялись prompt/extraction/оркестрация/DTO.
Смысл funding не сокращён до автоматического предположения о кредите.

Review показывает отрасль, город, бюджет и статус черновика. Полный редактор открывается
по «Изменить», остальные вводные доступны без огромной таблицы по умолчанию.
Переход не симулирует подтверждение и не обходит missing_fields/CAS/consent.

## Карта и аналитика

MapLibre, данные и scoring API сохранены. Фоновые POI — мелкие серые точки,
кандидаты — синие контуры/номерные маркеры, выбранный — заливка/выделение списка.
Выбор карты и списка синхронизирован, у кнопок есть aria-pressed. Показаны только
реальные зоны, null score остаётся отсутствующим. Зона не называется свободным помещением.

Основной экран — карта и компактный список. В «Подробнее о зоне и анализе» доступны
сравнение, составляющие рейтинга, качество/покрытие, настройки весов, walking/catchment
и переключение источников BA-014. Отсутствующие данные не подменяются синтетикой.
Пешеходный анализ и набор провайдера попадут в экспорт только если действительно рассчитаны.
Базовый георейтинг не зависит от финансов и банковского подбора.

## Финансы

Три основных редактируемых поля: аренда, продажи в день, средний чек базового сценария.
Все прочие исходные параметры доступны в раскрываемом блоке. «Рассчитать сценарии»
явно запускает существующий backend с демонстрационными редактируемыми допущениями.
Это вводные, а не зашитые результаты. Дальнейшие изменения вызывают новый POST calculate.

Показаны стартовые вложения, постоянные расходы, бюджет, три операционных результата
и один график. Пессимистичный соответствует conservative API; формулы и значения не
менялись. Выручка, переменные расходы, безубыточность, чувствительность, формулы и
provenance доступны в деталях. Операционный результат не назван чистой прибылью.
Синтетические вводные обозначены до расчёта и на итоговом экране.

## Банковские возможности и документы

Небольшая последовательность вопросов вместо восьми полей сразу: РКО, регистрация,
необходимая помощь/стадия, карты, канал и информация о финансировании. Известный
подтверждённый источник средств учитывается, неизвестный ответ сохраняется null.
Все потребности можно вручную дополнить. Подбор через прежний защищённый API.
Назначение и причины краткие; источники, ограничения и прочий каталог — по запросу.
Демо-статус, отсутствие действующих условий и кредитного решения видны сразу.

Прежний LeadFlow доступен в «Демонстрационная заявка и согласия» со всеми отдельными
согласиями, preview, CAS, idempotency и локальной квитанцией. Экспорт не запускает заявку.
На итогах — выбранная зона и реальные расчёты, PDF как главный CTA, JSON как вторичный.
Устаревший снимок блокируется до обновления. Повтор загрузки после ошибки файла
не создаёт второй снимок и не расходует повторно квоту подготовки.

## Изменённые компоненты

- `App.tsx`, новые `flow.ts`, `FlowUI.tsx`: маршрут, guards, review, summary, consent dialog,
  error boundary и восстановление. Старые `ProductUI.tsx`/его тест и `product-shell.css` удалены.
- `Chat`, `Locations`, `Finance`, `FinanceChart`, `BankProducts`, `ReportExport`: новая подача
  существующих операций; `GeoMap` — цвета и размеры фоновых объектов.
- CSS: design-tokens + flow + analysis + responsive; прежний local font сохранён.
- MapLibre JS/CSS импортируются через lazy Locations/Suspense. Начальный JS307.63kB
  (gzip92.82kB), отложенный Locations1111.37kB (gzip305.33kB), worker516.71kB.
  Предупреждение Vite о крупном отложенном map chunk остаётся; старт больше его не загружает.
- Backend: только короткие серверные фразы и тест formatter. API/schema/migrations/
  финансовые и географические алгоритмы/банковские правила не менялись.

## Доступность и адаптация

Проверены viewport1440/768/390, отсутствие горизонтального overflow в чате/финансах/
карте/итогах, клавиатурный skip-link, Escape в consent dialog, неотмеченный checkbox,
видимый focus, labels, лог сообщений aria-live, кнопки выбора/прогресс, reduced motion.
Мобильные controls минимум48px; список под картой. Необходимая длинная аналитика
прокручивается вертикально; один экран означает одну задачу, не запрет scroll.
Полная история чата прокручивается отдельно, composer остаётся доступным.
Формальная сертификация WCAG2.2AA и полноценное исследование с пользователями не проводились.
Firefox/WebKit и аппаратная клавиатура смартфона в этом этапе не проверены.

## Ограничения и дальнейшая работа

Нет обещания доступности любого города/отрасли: покрытие части Казани, demo-input кофейни
не становится универсальной отраслевой моделью. Карта требует доступных OSM tiles
для фоновой подложки; зоны/результаты приходят из PostGIS. LLM может ошибаться и отвечать
долго; сохранены ошибки/retry без выдуманного успеха. Неотправленные черновики и расчёты
не переживают закрытие/reload, профиль/история переживают reload этой вкладки.
Сохранённый отчёт существует на backend, но новый экран после reload требует повторного
анализа; отдельный browser reports archive не добавлялся.

Это согласованная хакатонная переработка, не принятие открытой release security baseline,
не закрытие всех roadmap UX/U/UI задач. H-FINAL/BA-017/018 и следующие задачи не начаты.
Нужны отдельные решения для пользовательских интервью, других браузеров, полного a11y
и долговременного хранения аналитического прогресса. PR не объединять автоматически.
