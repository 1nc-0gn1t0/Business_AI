# BA-010: пользовательский интерфейс

BA-012 добавляет заключительный шаг после каталога: выбор продуктов, редактор
минимального payload, отдельные согласия, предпросмотр, подтверждение и локальная
квитанция. Управление и отзыв согласий находятся там же; перед первым сообщением
отдельное согласие assistant раскрывается в чате. Контракты и ограничения:
[CONSENT_LEADS.md](CONSENT_LEADS.md). Данные в ВТБ не передаются.

React 19 / TypeScript / Vite / MapLibre GL JS 6. Единый desktop-first workspace
с адаптацией под смартфон: чат и профиль, карта, сравнение зон, финансовая модель.
`apps/web/src/api-schema.d.ts` сгенерирован openapi-typescript 7 из FastAPI OpenAPI;
компоненты используют эти DTO. Геоаналитика, scoring и финансовые формулы остаются
на backend. Графики только масштабируют уже вычисленные значения для отображения.

Обновление типов после изменения backend-контрактов (API должен быть запущен):

```powershell
Invoke-WebRequest http://localhost:8000/openapi.json -OutFile apps/web/openapi.tmp.json
npx --prefix apps/web openapi-typescript apps/web/openapi.tmp.json -o apps/web/src/api-schema.d.ts
Remove-Item -LiteralPath apps/web/openapi.tmp.json
```

## Запуск и сквозной сценарий

1. Запустите Ollama с моделью по разделу README о локальной LLM.
   Новые веса для BA-010 не нужны. Проверьте `OLLAMA_BASE_URL` в локальном `.env`.
2. `docker compose up --build --detach --wait --wait-timeout 180`.
   Существующие volumes не удаляются. Нужен импорт BA-006; команды — в GEO_DATA.md.
3. Откройте http://localhost:5173 и напишите:
   «Хочу открыть кофейню в Казани. Бюджет — 2 миллиона рублей».
4. Qwen извлекает параметры; сервер валидирует их и сохраняет в PostgreSQL.
   Ответы на уточнения можно написать в чат или заполнить через
   «Редактировать профиль»: например формат `навынос`, собственные средства.
   Проверьте значения и нажмите «Подтвердить профиль».
5. «Найти зоны» запускает BA-007 и BA-008 через `/rankings`. Выберите зону
   на карте или карточкой; откройте сравнение, исходные факторы и происхождение.
6. В финансовой модели явно загрузите демо-допущения BA-009, проверьте их
   и нажмите «Пересчитать модель». Изменение аренды или продаж отправляется
   тем же финансовым API без перезагрузки. Старый результат помечается устаревшим.

Кнопка `＋` начинает новую гостевую беседу. Перезагрузка вкладки восстанавливает
текущую беседу и всю историю с пагинацией по 100 сообщений. Ключ доступа хранится
в `sessionStorage`, передаётся только заголовком `X-Conversation-Token`
к приватным conversation-маршрутам на том же origin. В URL, внешние карты,
аналитику и логи frontend он не отправляется. При закрытии вкладки доступ обычно
теряется; резервное копирование ключей и список прошлых гостевых бесед не реализованы.
Финансовые черновики и выбранные зоны живут в памяти вкладки, в отличие от истории.

## API и защита состояния

| Раздел | Существующие маршруты |
| --- | --- |
| Доступность API/БД | `GET /healthz` (не проверка Ollama) |
| Новая беседа | `POST /api/v1/conversations` |
| Профиль/история | `GET /api/v1/conversations/{id}`, `GET .../messages?offset=…&limit=100` |
| Сообщения Qwen | `POST .../{id}/messages` |
| Редактирование/подтверждение | `PATCH .../{id}/profile`, `POST .../{id}/profile/confirm` |
| Источники и карта | `GET /api/v1/geo/datasets`, `GET .../{slug}/pois`, `GET .../{slug}/districts` |
| Зоны и scoring | `POST /api/v1/geo/{slug}/rankings` (внутри вызывает генератор BA-007) |
| Финансы | `POST /api/v1/finance/calculate` |

Все изменения профиля передают `expected_version`; 409 вызывает обновление
профиля/истории с предупреждением, без автоматической повторной записи.
Ошибка или неоднозначный сетевой исход сохраняет черновик сообщения и предлагает
проверить историю. Профиль нельзя подтвердить при missing_fields. Его изменение
сбрасывает результаты геоанализа и финансов, а незавершённые запросы отменяются.
Загруженная геоверсия закреплена в запросах POI/полигонов/ranking.
Смена зоны сбрасывает финансовый черновик, чтобы контекст не смешивался.

nginx proxy_read_timeout увеличен с 10 до 180 секунд для локальной Qwen;
клиентский предел — 190 секунд. Backend-схемы и LLM-алгоритм сохранены;
два прежних шаблона ответа теперь направляют к доступным карте/финансам,
вместо устаревшего утверждения, что аналитика не подключена.
Режим `rules/stub` честно обозначается как «не LLM», скрытого fallback нет.

## Карта и воспроизводимость

- Реальные PostGIS GeoJSON: POI, административные полигоны; модельные геозоны
  поверх них. EPSG:4326, долгота/широта; площади и расстояния берутся из API.
- Жёлтый пунктир обозначает bbox фактической выгрузки. Наличие внешней подложки
  за границей не означает, что для этой территории загружены аналитические данные.
- На карте показываются первые **не более 500 POI выбранной категории**;
  ограничение явно подписано при `next_offset`. Остальные объекты существуют
  в наборе и используются серверной аналитикой; карта не заявляет показ всех POI.
- Начальный явный preset BA-008 для `kazan-centre`:
  bbox `(49.065,55.71,49.235,55.84)`, ячейки 500 м, интервал 1000 м,
  радиус scoring 500 м. Его можно отключить и увидеть ограничения по краям.
  Это операторский географический фильтр, не новая модель поиска на frontend.
- Настраиваются веса и роль конкурентов. По умолчанию три наблюдаемых фактора
  равноправны, конкуренты нейтральны; обоснование/политика/хэши/метрики из API
  доступны в деталях. Изменения применяются кнопкой пересчёта.
  Карточки упорядочены по серверному rank; зоны без оценки — отдельно в конце,
  с детерминированным ID-порядком. Числа не заменяются нулями при null.
- Это сравнительный географический контекст, не оценка доходности, спроса,
  пешей доступности или подтверждённых свободных помещений.

MapLibre и worker поставляются в локальной сборке; worker явно подключён через
Vite `?worker&url` согласно [документации MapLibre 6](https://maplibre.org/maplibre-gl-js/docs/guides/v5-to-v6-migration-guide/).
MapLibre — BSD-3-Clause; React, Vitest, Testing Library, openapi-typescript — MIT;
Playwright — Apache-2.0. Зависимости закреплены npm lock-файлом.

Подложка MVP — бесплатные raster tiles `https://tile.openstreetmap.org/{z}/{x}/{y}.png`.
Атрибуция © OpenStreetMap contributors видна на карте и ведёт на copyright;
аналитические OSM-данные — ODbL-1.0. Соблюдается
[политика серверов OSM](https://operations.osmfoundation.org/policies/tiles/):
обычные интерактивные запросы браузера с Referer и штатным кешированием,
без offline/prefetch/массового скачивания и скрывающего клиент proxy.
Это малонагруженный локальный MVP, без SLA. Для публичного масштабирования нужен
свой tile-server либо подходящий по лицензии провайдер и его атрибуция.
Vite допускает `VITE_MAP_TILE_URL` для другого OSM raster endpoint при разработке;
в Compose production такая настройка требует передачи на этапе build,
а не runtime ENV nginx. Сейчас контейнер использует стандартную подложку.
Без сети не будет raster-карты; локальные GeoJSON/список/расчёты остаются доступны.
Нужен WebGL; без него интерфейс сообщает причину и оставляет список зон.
Крупный MapLibre bundle вызывает предупреждение Vite о размере chunk;
это известное ограничение MVP, сборка завершается успешно.

## Финансовая достоверность

`finance-template.json` содержит только редактируемые входы из BA-009, без готовых
результатов. Загружается по явному действию пользователя. Экономические поля
помечены synthetic; редактирование не превращает прогноз в подтверждённый факт.
Бюджет — user_input; результаты — modelled. Деньги отправляются decimal-строками,
дни/продажи — целыми. Визуализируются три сценария, структура стартового капитала,
операционный результат, безубыточность и sensitivity ±10% одного фактора за раз.
График безубыточности сопоставляет продажи по допущению с порогом из API;
кривые выручки frontend не вычисляет. Влияние чувствительности берётся из API.

Нет измеренного спроса/аренды/свободных помещений. Зона передаётся только как
контекстная ссылка, без OSM-score в финансовом запросе. Операционный результат
не называется чистой прибылью или денежным потоком: налоги, кредитные платежи,
амортизация и окупаемость здесь не моделируются. Ограничения/формулы/версии/
снимки и происхождение доступны рядом с результатами.

## Проверки

```powershell
npm --prefix apps/web ci
npm --prefix apps/web run lint
npm --prefix apps/web run typecheck
npm --prefix apps/web test
npm --prefix apps/web run build
npx --prefix apps/web playwright install chromium
npm --prefix apps/web run test:e2e
uv tool run --from prek==0.5.4 prek run --all-files
```

Vitest/jsdom: явные fetch mocks, MapLibre заменён mock-компонентом, реальные
WebGL/LLM не заявляются проверенными. Playwright по умолчанию поднимает Vite
на 4173 и использует явно записанные mock-ответы; настоящие сервисы не нужны,
OSM tiles не скачиваются. CI Ubuntu/Windows выполняет frontend unit/API тесты,
Ubuntu — также mock Chromium workflow. Нет GPU и скачивания весов.
`tsconfig.build.json` исключает тесты из production typecheck: Docker context
frontend не содержит архивных `docs/examples`; полный `typecheck` тестов идёт в prek/CI.

Отдельный настоящий сценарий, после запуска Compose/Ollama и импорта OSM:

```powershell
$env:BA010_REAL = '1'
npm --prefix apps/web run test:e2e
Remove-Item Env:BA010_REAL
```

Без API mocks: проверяет Qwen/extraction_mode, город/категорию/бюджет, PATCH,
confirm, историю после reload, пять реальных зон и рейтинги, карту/выбор зоны,
настоящий POST финансов, изменение аренды и пересчёт, мобильную ширину 390 px,
отсутствие JS/console errors. Скриншоты и обезличенные факты проверки:
[docs/screenshots](screenshots/BA-010-verification.json).
Тестовые traces/HAR/video отключены: они могут сохранять заголовки гостевого доступа.
Не включайте их для реальной сессии при публикации артефактов.
