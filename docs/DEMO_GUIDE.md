# BA-016 · воспроизводимая демонстрация

Post-MVP checkpoint: [F-00 baseline](baselines/F-00_BASELINE.md),
[точный manifest](baselines/F-00-manifest.json),
[backup/изолированный restore](BACKUP_RESTORE.md). Это локальный MVP, не RC/пилот.

## Перед показом

1. Docker Desktop работает. Используйте уже загруженные OSM, walking graph и модель;
   **не запускайте Overpass во время презентации**. Веса не входят в Git.
2. Проверьте Ollama (`ollama list`, `ollama ps`), выбранную Qwen и переменные из README.
   Для контейнерной Ollama команда: `docker exec business-ai-ollama ollama list`.
3. Для синтетического раздела явным образом включите `DATA_DEMO_ENABLED=true` и заранее
   импортируйте версионированный набор по [DATA_PROVIDERS](DATA_PROVIDERS.md).
   Без этого раздел должен честно сообщать об отсутствии demo, не подменять данные.
   PowerShell: `$env:DATA_DEMO_ENABLED='true'` **перед** `docker compose up`.
   Новый shell без переменной снова использует false; `.env` автоматически не меняется.
4. `docker compose up --build --detach --wait --wait-timeout 180` сохраняет volumes.
5. Выполните readiness:

```powershell
uv run --locked --project apps/api python scripts/demo_ready.py --require-demo-data
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/smoke.ps1
```

Readiness проверяет health, точные версии [manifest](../data/demo-manifest.json),
наличие модели, демонстрационный каталог и при флаге synthetic. Все 7checks PASS
на BA-016. Скрипт ничего не импортирует/не удаляет/не отправляет и не выполняет inference.
Для доказательства Qwen нужен реальный ответ API и надпись «Локальная Qwen · Ollama».
`LLM_PROVIDER=stub` — только явно обозначенный offline rehearsal, не live-диалог.

Проверенные версии: OSM44157bdc…, graph a63822ae…, synthetic adf6964b…;
полные SHA в manifest. Смена источника требует повторных расчётов/обновления отчёта.
Не отключайте проверку stale ради зелёной readiness; обновите и проверьте источник.

## Сценарий презентации (живые запросы)

1. Откройте http://localhost:5173/. «Новая беседа» создаёт новую сессию, не удаляет
   старые записи. Сохраните старую вкладку, если нужен доступ к прежней беседе:
   её guest key находится в sessionStorage. Не копируйте его в URL/видеозапись/логи.
2. Предоставьте отдельное согласие на ассистента. Напишите:
   «Хочу открыть кофейню в Казани. Бюджет — 2 миллиона рублей».
3. Дождитесь Qwen. Проверьте профиль глазами; формат «навынос», средства «свои»
   можно уточнить сообщениями либо редактором. Подтвердите профиль.
4. «Найти зоны»: реальные OSM Казани, несколько зон, сравнение факторов/весов.
   Объясните: зоны не помещения, рейтинг не прибыльность.
5. Walking: точка 49.119,55.788/600 м, реальные достижимые участки/POI. Это выбранная
   точка, не доказанный вход в помещение; сетевое расстояние отличается от прямого.
6. Источники: сначала real OSM, затем явно demo synthetic. Покажите origin/дату/версию;
   условный поток/аренда не рыночные измерения и не меняют рейтинг автоматически.
7. Финансы: загрузите **синтетический пример кофейни**. Посмотрите три сценария;
   измените аренду 80000→100000: базовый операционный результат 285000→265000₽.
   Это операционный результат до неучтённых налогов/кредитов, не чистая прибыль.
8. Продукты: укажите явные потребности (ИП, офлайн, РКО/приём карт), покажите причины
   и источники. Каталог демонстрационный; кредитоспособность не оценена.
9. Подготовьте отчёт, скачайте PDF/JSON. Измените вводную — старое скачивание должно
   блокироваться до пересчёта. Экспорт не требует согласия на отправку заявки.
10. При желании отдельно: выберите продукт/поля, проверьте preview, разрешите
    demo_lead (маркетинг можно отклонить), подтвердите состав и mock-операцию.
    Квитанция: «Демонстрационная заявка создана. Данные в ВТБ не отправлены».

Это инструкция, а не записанный диалог. Ответы/длительности Qwen могут отличаться.
Сначала прогрейте модель отдельной вымышленной беседой, потом начните новую;
холодный первый запрос в оценке занял 71 с, тёплые обычно 2–9 с.

Альтернативные проверенные пути: пекарня/Казань/500 тыс (дефицит модельного бюджета),
автосервис/Самара/10 млн (нет геопокрытия; финансы работают независимо).
Другим отраслям пример кофейни нельзя представлять как отраслевую модель.

## Восстановление без удаления данных

| Симптом | Действие |
|---|---|
| 503/Ollama | проверьте процесс/порт 11434, имя модели и OLLAMA_BASE_URL; сохранённый текст отправьте повторно |
| 504/долгий первый ответ | дождитесь завершения/прогрева, проверьте память и `ollama ps`; не переключайте на stub незаметно |
| 502/неверное извлечение | исправьте профиль вручную, проверьте сумму/город до подтверждения; не выдавайте это за успех Qwen |
| 409/другая вкладка | обновите состояние, проверьте актуальные вводные, повторите осознанную правку |
| Нет данных/рейтинга | проверьте город, coverage, версию; не используйте synthetic как fallback |
| Postgres недоступен | `docker compose ps`, восстановите db/api; не удаляйте volumes |
| Ошибка тайлов | проверьте интернет для OSM-подложки; локальные геометрии/расчёты и PDF независимы от Overpass/тайлов |
| Отчёт/черновик устарел | пересчитайте/обновите и подтвердите заново |
| Согласие отозвано | управление в продуктах/согласиях; нельзя обходить серверные проверки |

## Изолированная среда live evaluation / browser QA

Не запускайте массовые фиктивные диалоги в рабочей БД. BA-016 использовала отдельную
`business_ai_eval_ba016`. Если она уже существует, не перезаписывайте и не удаляйте её.
Для новой среды (однократно, из корня; имя/порт должны быть свободны):

```powershell
docker exec business-ai-db-1 createdb -U business_ai business_ai_eval_ba016
docker compose run --rm --no-deps -e PGDATABASE=business_ai_eval_ba016 migrate
# Копируются только открытые/синтетические данные, без conversations/leads/reports
docker exec business-ai-db-1 sh -c 'pg_dump -U business_ai -d business_ai --data-only -t geo_datasets -t geo_pois -t geo_districts -t walk_graphs -t walk_edges -t provider_datasets | psql -U business_ai -d business_ai_eval_ba016 -v ON_ERROR_STOP=1'
docker compose run --detach --no-deps --name business-ai-ba016-eval -p 127.0.0.1:8016:8000 -e PGDATABASE=business_ai_eval_ba016 -e DATA_DEMO_ENABLED=true -v "${PWD}/apps/api/app:/app/app:ro" api
```

Перед копированием убедитесь в чистой новой целевой БД; повторный импорт через pg_dump
не предназначен для обновления. Нормальные воспроизводимые импорты — по документации
BA-006/013/014. Для другой установки измените POSTGRES_USER/имя рабочей БД осознанно.
После QA можно остановить только `business-ai-ba016-eval` и тестовый Vite;
данные/volumes автоматически не удаляются. Команды оценки и browser — в
[LLM_EVALUATION](LLM_EVALUATION.md), [E2E_REPORT](E2E_REPORT.md).

Готовность: управляемое локальное демо возможно; это не готовность к публичному
банковскому пилоту. До него нужны оставшиеся security/operations/legal/data работы.
